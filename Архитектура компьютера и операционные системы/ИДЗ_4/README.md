## Задание
Разработать программы, состоящие из нескольких взаимодействующих параллельных потоков. Количество разрабатываемых программ и их характеристики определяются в соответствии с требованиями выполнения на соответствующую оценку.

### Вариант 30 - Военная операция
Темной–темной ночью прапорщики Иванов, Петров и Нечепорук занимаются хищением военного имущества со склада родной военной части. Будучи умными людьми и отличниками боевой и строевой подготовки, прапорщики ввели разделение труда. Иванов выносит имущество со склада и передает его в руки Петрову, который грузит его в грузовик. Нечепорук стоит на шухере и заодно подсчитывает рыночную стоимость добычи поле погрузки в грузовик очередной партии похищенного.

Требуется составить многопоточное приложение, моделирующее деятельность прапорщиков–потоков. Необходимо учесть случайное время выполнения каждым прапорщиком своей боевой задачи и организовать в программе корректную их синхронизацию.

## Сценарий в предметной области

- **Иванов** поочередно выносит партии имущества случайного размера (от 5 до 20 единиц).
- **Петров** забирает каждую вынесенную партию и грузит её в грузовик.
- **Нечепорук** после каждой погрузки вычисляет стоимость партии (базовая цена 1000 руб./шт. + случайная надбавка до 5000 руб.) и ведет общий учёт.

Потоки работают последовательно: Петров не может грузить, пока Иванов не вынесет партию; Нечепорук не может считать, пока Петров не погрузит.

## Модель параллельных вычислений

Используется парадигма **«производитель-потребитель»**:

- Иванов — производитель данных (партий).
- Петров — потребитель данных Иванова и производитель для Нечепорука.
- Нечепорук — конечный потребитель.

Синхронизация осуществляется через:
1. **Семафоры и мьютексы** (программа `main_for_8.c`).
2. **Условные переменные и мьютексы** (программа `main_for_9-10.c`).

## Входные и выходные данные

### Входные параметры:
- Количество партий для кражи (от 1 до 100).
- Возможные источники ввода:
  - Аргумент командной строки.
  - Конфигурационный файл (ключ `-c`).
- Имя выходного файла (ключ `-o`), если требуется запись результатов.

### Генерация случайных данных:
- Размер партии: `5 + rand() % 16` (5–20 единиц).
- Время выполнения операций:
  - Иванов: 1500–3000 мс.
  - Петров: 1000–2000 мс.
  - Нечепорук: 500–1000 мс.
- Стоимость партии: `1000 * размер + rand() % 5000` (руб.).

### Выходные данные:
- Ход операции в реальном времени.
- Итоговая статистика:
  - Количество партий.
  - Общая стоимость.
  - Счётчики действий Иванова и Петрова.
 
## Обработка сигналов прерывания

Программы корректно обрабатывают сигналы:
- `SIGINT` (Ctrl+C) - прерывание с клавиатуры
- `SIGTERM` - сигнал завершения

При получении сигнала:
1. Выводится предупреждение "ТРЕВОГА! Поступила команда на срочное прекращение операции!"
2. Завершаются текущие операции потоков
3. Выводятся итоговые данные по обработанным партиям

Пример прерывания показан в тесте 3 (25 партий).

## Реализация

### Программа на 8 баллов (`main_for_8.c`)

**Используемые примитивы:**
- Именованные семафоры (`sem_t`).
- Мьютексы для защиты общих данных.

**Особенности:**
- Ввод через командную строку или конфигурационный файл.
- Вывод в консоль и/или файл.
- Обработка сигналов `SIGINT` и `SIGTERM` для экстренной остановки.

**Пример запуска:**
```bash
./main_for_8 -c input.txt -o output.txt
```

### Программа на 9–10 баллов (`main_for_9-10.c`)

**Используемые примитивы:**
- Мьютексы (`pthread_mutex_t`).
- Условные переменные (`pthread_cond_t`).

**Особенности:**
- Альтернативный механизм синхронизации.
- Те же возможности ввода/вывода, что и в первой программе.

**Пример запуска:**
```bash
./main_for_9-10 -c input.txt -o output.txt
```

## Сравнительный анализ двух реализаций

| Критерий | Реализация с семафорами (`main_for_8.c`) | Реализация с условными переменными (`main_for_9-10.c`) |
|----------|-------------------------------------------|--------------------------------------------------------|
| **Механизм синхронизации** | Именованные семафоры + мьютекс | Условные переменные + мьютекс + флаги состояния |
| **Читаемость кода** | Проще для понимания линейного потока | Более сложная структура с `while`-циклами и флагами |
| **Порядок действий** | Иванов -> Петров -> Нечепорук чередуется с параллельной работой (Иванов успевает вынести несколько партий до их обработки) | Строгий последовательный порядок: Иванов -> Петров -> Нечепорук для каждой партии |
| **Параллелизм выполнения** | Высокий — потоки работают асинхронно | Низкий — потоки работают строго синхронно |
| **Скорость выполнения** | Быстрее из-за асинхронности | Медленнее из-за строгой синхронизации |
| **Вывод в консоль** | Быстрый, сообщения перемешиваются от разных потоков | Медленный, но последовательный и понятный вывод |
| **Устойчивость к ложным пробуждениям** | Защищена семафорами | Явная защита через `while`-проверки флагов |
| **Обработка прерываний** | Быстрая реакция, но рассинхронизация счетчиков | Быстрая реакция, но рассинхронизация счетчиков |
| **Результаты при одинаковых входных данных** | Случайные значения (размер партии, стоимость) из-за разных seed | Случайные значения (размер партии, стоимость) из-за разных seed |

### Вывод:
Условные переменные обеспечивают строгий порядок и надёжность благодаря явной синхронизации, делая выполнение предсказуемым.

Семафоры дают высокую скорость и простоту за счёт минимальных накладных расходов и максимального параллелизма.

## Инструкция по запуску

### Компиляция:
```bash

gcc -pthread main_for_9-10.c -o main_for_9-10
```

### Примеры запуска:
1. **Базовый запуск (15 партий):**
   ```bash
   ./main_for_8
   ./main_for_9-10
   ```

2. **С конфигурационным файлом:**
   ```bash
   ./main_for_8 -c test.txt -o result_for_8.txt
   ./main_for_9-10 -c tset.txt -o result_for_9-10.txt
   ```

3. **С аргументом командной строки:**
   ```bash
   ./main_for_8 6 -o output.txt
   ./main_for_9-10 6 -o output.txt
   ```

4. **Одновременный запуск для сравнения:**
   ```bash
   ./main_for_8 -c test.txt -o result_for_8.txt &
   ./main_for_9-10 -c tset.txt -o result_for_9-10.txt &
   wait
   ```
